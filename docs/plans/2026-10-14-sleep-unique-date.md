# life_sleep 一天一筆（unique date）Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 由資料庫保證 `life_sleep` 同一個起床日（`date`）最多一筆、同時最多一筆睡覺中紀錄，並移除 App 中為「同日多筆」存在的程式。

**Architecture:** 加 `UNIQUE (date)` constraint（NULL 彼此不同，尚未起床的 session 不受它限制），另加 partial unique index 保證同時最多一筆 session（`sleep_time` 有值且 `wake_time` 為 null）。`lib/sleep.js` 只在錯誤訊息點名這兩個名稱時才把 `23505` 轉成中文；撞日期時頁面直接打開既有那筆。任何 action 失敗都 refresh，避免 stale state 讓使用者重試同一個錯。頁面改用 `find` 取當日唯一一筆，刪除 `DayRecordsSheet`。`id` 保留為內部主鍵。

**Tech Stack:** Supabase Postgres 17（project `ukmcixycjqrznctudzrx`）、Next.js 16、React 19。

**Spec:** 無正式 spec；需求來自 2026-10-14 對話（使用者選擇「保留 id + 加唯一規則，同一天只有一筆」，否決「date 當主鍵」）。

- 287 筆有 date 的列、287 個不同 date、重複 date = 0、空白列（sleep/wake 皆 null）= 0。
- `life_sleep` 的讀寫只在 `lib/sleep.js`（家目錄全域 grep 確認）。

## Plan review（codex adversarial，2026-10-14 round 1）

| # | 發現 | 處置 |
|---|------|------|
| 1 | UNIQUE(date) 對 NULL 不設限，兩台裝置或 PWA 快取的舊版仍可產生多筆 session；舊的那筆之後無法以同一天起床 | **已修**：加 partial unique index `life_sleep_single_open_session`，DB 層保證最多一筆 session |
| 2 | 撞日期後提示「點那天的卡片」，但 records 是舊的會再開空白表單；7 天以外的日期根本沒有卡片 → 無限重試 | **已修**：撞日期時查那一天、直接打開既有那筆；`handleAction` 失敗一律 `refresh()` |
| 3 | 所有 `23505` 都當成撞日期，會掩蓋主鍵序列落後等真正的資料庫問題 | **已修**：只在錯誤訊息含兩個 constraint 名稱時轉換，其餘原樣；已查序列未落後 |

Round 2：發現 migration 檔放進 `supabase/migrations/` 會讓 fork 的乾淨安裝在 `life_sleep` 不存在時失敗 → **已修**：不建 migration 檔，SQL 只留在本 plan，依 `AI_ONBOARDING.md` 由使用者在 Studio 執行。

## Review Focus

1. **編輯某筆把日期改成另一個已有紀錄的日期（含 7 天以外）** → 被拒，兩筆都不變，並直接打開那天既有的紀錄。
2. **今天已有完整紀錄，又有一筆 session 在等起床，按起床** → 被拒，session 保持開著，可由 banner 打開後刪除或改日期（不會卡死）。
3. **今天有 placeholder（date 有值、時間空白）且有 session，按起床** → 同 2 被拒；目前 DB 無 placeholder，使用者也不再手建，接受。
4. **migration 在有重複 date 時執行** → `ALTER` 失敗、不改任何東西（constraint 建立是原子的）；Task 1 先跑重複檢查。
5. **已有 session 時再新增 session（兩台裝置／舊版快取）** → 被 `life_sleep_single_open_session` 拒絕，提示「已經有一筆睡覺中的紀錄」，頁面 refresh 後 banner 出現。

- [ ] **Step 1: 要執行的 SQL**

```sql
-- life_sleep: one record per wake date (2026-10-14, run in Supabase Studio)
-- One record per wake date. Open sessions (date is null until 起床) stay
-- unconstrained because UNIQUE treats NULLs as distinct.
-- Pre-check 2026-10-14: 287 dated rows, 0 duplicate dates.
-- At most one open session (sleep_time set, wake_time null); placeholders
-- (both times null) are not sessions. Pre-check 2026-10-14: 0 open sessions.
-- lib/sleep.js translates unique_violation (23505) only when the message
-- names one of these two objects.

alter table public.life_sleep
  add constraint life_sleep_date_key unique (date);

create unique index life_sleep_single_open_session
  on public.life_sleep ((true))
  where sleep_time is not null and wake_time is null;
```
